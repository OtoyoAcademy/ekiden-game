EKIDEN RACE LAB　駅伝レースシミュレーター（試作版 v1.0）

■ 最初の使い方
1. index.html をブラウザで開きます。GitHub Pagesに公開すると、スマートフォンやタブレットでも同じURLを利用できます。
2. 「レースゲーム」→参加人数1〜5人、名前、重複しないチーム、応援選手（強・普通）を設定→スタート。
3. 「計測テスト」→チーム数、区間数、基準秒数を設定→スタート。タイマーとの実時間比較では必ず「1倍速」を利用してください。
4. 「選手・画像」から各チームの走行キャラクター画像、および選手3人の名前とイラストを登録できます。計測テスト向けに10チームまで用意しています。
5. レース終了後に「このレースを保存」。保存レース一覧から再生・削除・JSON出力できます。

■ 採用したゲームルール
・5チーム固定、1〜5人が1端末で遊ぶ。空きチームはCPU。プレイヤー同士でチームは重複しない。
・各チーム3人が計6区間を、1人が1区間、もう1人が2区間、もう1人が3区間走る。
・各区間の基本タイムは15〜25秒で、チーム合計は全チームちょうど120秒。
・「激しく応援」対象は走る1区間ごとに3秒短縮、「普通に応援」は1秒短縮、残りは効果なし。
・最終区間にチームごと±0.5秒の調子変動。担当区間はゴールまで非公開。
・CPUにも同じ応援条件を適用する。ゲーム終了時に順位と選手の担当区間を公開。
・シリーズ成績はプレイヤー別の優勝回数、出場回数、獲得ポイント（順位に応じて5〜1点）。

■ 計測テスト
・初期設定は10チーム×9区間、基準20秒、各区間±5秒。1区間目に同時通過を含める設定あり。
・区間通過・合計タイムは生成されたミリ秒単位の値に従う。
・テストモードには応援効果を入れない。速度倍率は再生の速さだけに影響し、記録値は変わらない。

■ 保存について
・選手名など簡単な設定は localStorage、キャラクター画像・選手画像とレースは IndexedDB に保存。
・ブラウザの閲覧データを削除すると消えることがあるため、重要なレースはJSONで書き出して保管。
・保存レースのJSONには、そのレースで使った選手画像・名前と区間タイムが含まれる。
・JSONの取り込み先に同名レースがあっても、新しい記録として追加される。
・サーバーやSupabaseは使わず、GitHub Pagesだけで公開可能。

■ GitHub Pagesでの公開
GitHubリポジトリのルートに index.html を置いて Settings > Pages > Deploy from a branch で main / (root) を選択して公開。

■ 試作版の注意
・端末やブラウザをまたいだ自動同期はありません。JSONで移行してください。
・他のアプリの計測操作をプログラムで直接制御する機能はありません。表示された通過時刻と照合します。
・端末の負荷やブラウザのバックグラウンド状態で見た目のアニメーションが遅延することがあります。計測の基準は内部で生成した予定通過時刻です。
